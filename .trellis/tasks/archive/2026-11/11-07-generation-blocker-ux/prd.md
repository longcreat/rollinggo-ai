# PRD: 修复「生成必失败」与失败态死路

## 现象（C 端，2026-11-06 23:29 截图）

- 成都 4 天 + 美食偏好：规划 Agent 正常排完 4 天（6–7 个/天），最后仍报
  `规划结果不完整（第1天7个｜…，候选 17 个）：第 1 天缺少午餐…第 4 天缺少晚餐…。请重试`。
- 失败页只有「回首页」一个按钮，用户三分钟的等待以回到起点结束；页签仍显示「正在生成」。

## 根因

1. **餐次校验跑在餐次补齐之前**：`draft.validate()` 在规划 Agent 提交后立刻执行，要求美食偏好下每天有午晚餐；
   而 `ensureMealCoverage()`（确定性补餐）只被单测调用，编排链路里从未接入，`enrichMealAnchors()` 又在
   `resolveGeoAndSimulate()` 里、校验之后才跑。于是 **任何带美食偏好的行程 100% 失败**。
2. **规划 Agent 只选景点**：`plan_day` 把活动类目固定写成 `文化`，也没有餐厅检索工具（提示词明说餐次由后续程序补），
   所以餐次必须由后处理补，否则校验永远过不了。
3. **重排时刻会把餐次挪出饭点**：`applyDraftTimings` 纯按「上一站离开 + 通勤」顺延，插入的 18:00 晚餐会被排到 16:03。
4. **失败终态无出口**：`LiveAgentStream` 失败时只渲染「回首页」，`useGenerationRun` 也没有保留整单表单参数。

## 修复

1. 编排接入 `ensureMealCoverage`（仅 `isFoodFocused(preferences)`，与校验判定同口径），放在 geocode 之后、
   `enrichMealAnchors` 之前，补出的锚点再由 enrich 换成真实餐厅。
2. 完整性校验后移到所有后处理之后（落库前）：天数/空天仍硬失败，餐次与跨天重复降级为日志 + 备注，不再让整单失败。
3. `applyDraftTimings` 对餐次做时间窗对齐：午餐不早于 11:30、晚餐不早于 17:30（宁可白天留白，不出现 16:00 晚饭）。
4. `ensureMealCoverage` 只在活动**整段盖住**用餐窗口（远郊一日游）时才整合成「含午餐安排」，边缘重叠改为插入，
   避免「博物馆（含午餐安排）」这种错标。
5. 失败态：`LiveAgentStream` 增加「重新生成一次」，失败时把表单参数（`tw.lastTripDraftParams`）留档，
   一键回到 `/trips/new` 自动重发；顶栏状态与标题按终态显示「生成未完成」，不再假装「正在生成」。
6. 美食偏好时提示词把每天景点数收敛到 5 个左右，给午晚餐留出时间。

## 非目标

- 不重写规划 Agent 的选点/排程；不引入新的餐厅检索工具。
- 不改生成之外的详情对话链路。
- 不提交工作区其他 WIP。

## 验收

1. 浏览器端到端（Playwright + 本机 Chrome）跑通成都 4 天美食行程：3 次成功，落库行程含每天午晚餐、
   餐次落在饭点，跨天无重名。
2. 失败态注入（伪 EventSource 触发 job_error）：页面出现「重新生成一次」「回首页调整条件」，点击重试回到
   `/trips/new?...&autostart=1` 并自动重发。
3. `npm run typecheck` 四包通过；`doppler run -- npm run eval:test` 106 项通过；
   mealPlanning / mealEnrichment / dayPlanner 单测全过。
## 追加（00:20）：详情页对话里说「重新规划改成长沙三日游」像是什么都没发生

- 现象：对话回「条件已更新、请求已提交」，然后就没有然后了，页面停在聊天。
- 根因 1：`ChatPanel` 收到 `autoStartedJobId` 后 `navigate('/trips/new')`（空参）。该页依赖
  GenerationProvider 的恢复流程，而 provider 在挂载时已判定「无进行中任务」，不会再跑恢复；
  守卫随即把它踢回首页 —— 用户看到的「直接结束」就是这个跳转。
- 根因 2：那次生成其实起来了（23:40 的长沙任务），但 11-09 是周一、长沙博物馆闭馆，
  落库前的闭馆硬校验把整单判失败；失败只落在通知里。
- 修复：
  - 客户端直接 `navigate('/agent/<autoStartedJobId>')`，直播页立刻接管（实测 10s 进入）。
  - 服务端在「要求重新生成但没启动」时写 `attachment.notice` 说明原因（已有任务在跑 / 今日次数用完）；
    目前只在有任务并发或额度耗尽时触发，日常路径不会出现。
  - 规划工具层把闭馆变成硬拒绝：`plan_day` 遇到闭馆地点直接返回错误要求换点，`submit_plan` 再兜一次；
    不再等到落库前才整单失败。
- 验证：重放同一句「重新规划改成长沙三日游，偏好保持不变」→ 10s 进直播页 → 生成成功
  `长沙三日·山水洲城舌尖行`（24 站，含每日午晚餐）。
