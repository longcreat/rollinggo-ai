## 行程图片显示逻辑梳理（排查「行程中图片问题」）

梳理了 trip-weaver 行程中图片从生成到展示的完整链路：

- **数据模型**：`ResearchPoi.coverUrl / coverAttribution / photos(≤3)`（packages/shared/src/schemas.ts L111-123），photos 含首选封面；旧行程可仅 coverUrl。
- **生成时选图**：researchTools.ts `resolveCover` 优先级 = 外部已存选择(Pexels/Pixabay/Unsplash/Commons) → 高德 search_pois 旁路(2026-11-05 新增，photoUrlsByName) → 实时 Pexels/Pixabay/Unsplash/Commons → 小红书图库 → 高德兜底。正式生成入口 `reviewedCover=createGenerationPhotoLookup`（人工选图优先）；仅 attraction 补图。
- **读取时补空图**：GET /trips/:id → `enrichTripPhotos`（tripPhotoService.ts）只补 attraction 且完全无图的候选，不写回历史。
- **前端匹配**：tripDerive.ts `matchOverview` 按名称归一化匹配 activity↔overview 候选（精确优先，包含匹配有防误报护栏）；失配则 matchedPoi 为空 → 活动卡无封面。
- **展示**：ActivityCard 右侧 72px `PoiCover`（失败回类目图标）；ActivityDetailModal 顶部画廊 `photos ?? [coverUrl]` + 圆点切换 + PhotoCredit；PoiCard variant=photo 走 `PoiPhotoGallery`（最多 3 张去重、剔除加载失败、Modal 大图左右切换）。
- **失败兜底**：PoiCover/PoiPhotoGallery 均有 onError → 类目图标占位；ActivityCard 存 failedCover 状态但当前未消费（死状态）。
